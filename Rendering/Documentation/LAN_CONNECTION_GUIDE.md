# 同じLANの2台で対戦する

## 通常の接続

両PCで同じexeと素材を使い、同じLANに接続します。VERSUS → LAN接続 / オンライン対戦を開き、自分の操作機器を選びます。
ホストが先に「部屋を作成（1P）」、参加側が「同じLANの部屋を探す / 再検索」を押して、見つかった部屋を選びます。
検索は5秒、部屋の参加待ちは60秒。待機期限が切れたら作り直します。参加側の待受ポートは自動です。
結果画面で双方が「再戦の準備完了」を押すと再戦します。Esc / Optionsで試合中のメニューを開き、音量・復帰・切断を選べます。オンライン中はメニューを開いても試合は進みます。

## パッド操作

十字キー/左スティックで選択、A（×）で決定・調整開始、B（○）で調整終了・戻る、左右で値を変更します。
L1/LBは細かく、R1/RBは大きく調整。キーボードの方向キー・Enterとマウスも使えます。
同じLANの通常接続はIPを入力しません。自動検索で見つからない場合だけ詳細設定を使います。

## 検索で見つからない場合

「詳細設定：LAN接続先を入力」を開きます。ホストは表示された自分のIPv4:ポートをコピーして相手へ伝えます。
参加側は「クリップボードから入力」、キーボード、または「パッドで数字を入力」を使い「入力した接続先へ参加（2P）」を押します。
接続先の例は192.168.1.10:27020です。127.0.0.1は自分自身なので、同じPCで2つ起動する確認にだけ使います。
「開発用：IPとポートを個別に指定」は、指定ポートでの確認用です。同じPCでは待受ポートを別にします。
学校のネットワークで端末間通信が許可されている必要があります。ゲームはOSやネットワークの通信設定を変更しません。

## 実装の入口と確認

Networking/LanDiscovery.hが部屋の検索・応答、UdpTransport.h/.cppが非ブロッキングUDPと表示用IPv4列挙、ConnectionAddress.hがIPv4:portの生成・検査を担当します。
2週間制作のOnlineBattle.cppがUIから既存start_online_battleへ渡し、RoomHandshake/PeerChannelが接続後の開始状態・入力同期を担当します。
MenuGamepadNavigation.hとFighterInput.cppの接続は[CONTROLLER_MENU_GUIDE.md](CONTROLLER_MENU_GUIDE.md)を参照してください。
アドレス一覧は画面初回と更新ボタンで取得し、毎描画で列挙しません。無効・ループバック・リンクローカルのアダプターは一覧から除きます。
部屋やソケット、UI入力は実時間の状態です。Component、Inspector、Scene/Prefab保存・複製・Undoへは接続していません。
共通部品はチーム・個人・2週間制作に反映し、ゲームの接続UIは2週間制作で呼びます。Editor全体へのパッド操作接続ではありません。

NetworkTestsのDebug/Releaseは不正な接続先・実UDP検索・同期を、MenuNavigationTestsは実ImGuiの選択・決定・音量調整と入力抑止を検証します。
ゲームもDebug/Releaseでビルドし、実UDPの2プロセステストで再戦まで確認します。
v02はユーザーから同じLANの実機2台で正常動作の報告あり。新しいパッド操作の実機操作感は別途確認が必要です。
オンライン対応は同じLAN内が対象です。別ネットワーク向けの接続サービスや補助アプリ連携は組み込みません。
