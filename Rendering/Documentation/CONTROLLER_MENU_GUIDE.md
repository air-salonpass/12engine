# 設定・接続画面をコントローラーで操作する

## 操作

対応する画面はVERSUSの対戦方式、LAN接続・LAN接続先の手入力、オンライン中のメニュー・再戦・切断、オフラインの音量・VSync・FPS設定です。
十字キーまたは左スティックで項目を選び、A（PSの×）で決定します。スライダーはAで調整を開始し、左右で変更、B（○）で調整を終了します。
L1/LBは細かく、R1/RBは大きく調整します。B（○）は選択一覧や入力パネルを閉じ、調整中でなければ前の画面へ戻ります。
数字入力はパッド用パネルの数字・小数点・コロンを選んで入力します。マウスとキーボード入力も利用できます。

## 呼出しと変更箇所

Systems/MenuGamepadNavigation.hは、接続済み・ボタン・軸を正規化したmenu_padからImGuiのナビゲーション入力を作ります。
2週間制作のFighterInput.cppは、既存のDualSense/native_controllerとXInput取得後にmenuPadsへ入力を記録します。
framework.cppはImGui_ImplWin32_NewFrameの直後、ImGui::NewFrameの直前にapply_frontend_navigationを呼びます。Win32側のXInput専用入力に上書きされない順序です。
frontend_widgets_activeが有効な画面だけUIへ流し、従来のfrontendAccept/Nextと二重実行しないよう抑止します。
画面遷移後は方向・決定ボタンを離すまでパッド入力を遮断します。ポップアップ・値調整中のBを、画面全体の戻るとして重ねて処理しません。
非アクティブウィンドウではパッド入力を送らず、通常の戦闘中はUIナビゲーションを無効にします。
パッドメニューの状態は試合チェックポイントに保存しません。Scene/Prefab保存・Inspector・複製・Undoへも接続しません。

共通ヘルパーとMenuNavigationTestsは両エンジンにも配置しましたが、Editor全体の全項目をゲームパッドへ接続したわけではありません。
別ゲームへ導入するときは既存の入力取得からmenu_padを作り、描画のNewFrame直前で呼び、旧メニュー操作との二重処理を避けてください。
Tools/MenuNavigationTestsをDebug/Releaseでビルドすると、実際のImGuiボタン選択・決定・スライダー変更と、押しっぱなし抑止・フォーカス外・戦闘時の無効化をCPUだけで確認できます。
物理パッドでの接続画面→機器変更→部屋検索→参加、オンラインメニューからの復帰、再戦、切断は実機で確認してください。
