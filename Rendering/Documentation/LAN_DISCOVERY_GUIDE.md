# 同じLANの部屋検索

## LANの部屋を自動で探す（2026-10-28追加）

ゲームの接続画面で自分の操作機器を選び、ホストが「部屋を作成（1P）」を押します。
参加側は「同じLANの部屋を探す / 再検索」を押し、表示された部屋のボタンを押します。
IPとホストのポートを応答から取得し、参加側の待受ポートはOSが空き番号を選ぶため、通常は数字を入力しません。
先にホストを作ってから検索してください。検索は5秒間、待機は60秒です。待機期限後は作り直します。
複数の部屋が見つかった場合はIPとポートで相手を確認してください。自動で最初の相手に接続はしません。
見つからないときは再検索か「詳細設定：IPを手入力して接続」を利用できます。
127.0.0.1は自分自身のPCです。別PCへの手入力接続にはホストのLAN内IPv4が必要です。

Networking/LanDiscovery.hが検索専用ソケットを所有します。ホストはUDP27019で、ゲーム番号を含む24バイトの検索に同じ長さで応答します。
参加側は一時ポートから0.5秒ごとに255.255.255.255と127.0.0.1へ検索します。応答の送信元IPと広告されたゲーム用ポートを一覧へ追加します。
毎描画のpoll_online_battleがupdateを呼び、ホストが参加相手を固定した後は広告ソケットを閉じます。
検索nonce、ゲーム番号、形式、ポートを検査し、受信は1描画32件・応答8件・一覧32件までです。
開始State・exe・素材の互換性検査は既存のRoomHandshakeが接続時に行います。検索結果は認証済みを意味しません。
検索処理は戦闘状態の巻き戻し・Component・Inspector・Scene/Prefab保存・複製・Undoには接続しません。部屋やソケットは実時間だけの状態です。
共通部品はチーム・個人・2週間制作へ反映、接続UIは2週間制作のみです。

同じLANでブロードキャストとPC間UDP通信が許可されている必要があります。別LAN、NAT越え、中継、学校の端末隔離を越える機能はありません。
検索用UDP27019とゲーム用UDPの両方が必要です。ファイアウォールを無効にせず、利用環境の許可に従ってゲームを許可します。
複数NICでは検索が利用中LANへ届かない場合があるため、手入力接続を残しています。1台で自動案内できるホストは1つです。

確認はTools/NetworkTestsのDebug/Releaseで不正形式・別ゲーム・実UDP検索を検証し、ゲームの両構成をビルドします。
実画面では2つ起動して、作成→検索→一覧から参加→切断→再検索を確認します。
別PC・学校LANの到達性は別途実機確認が必要です。旧配布版には検索UIがないため、両PCとも同じ新しい配布版を使います。

2026-10-28更新：v02で同じLANの2台対戦はユーザーから正常動作の報告あり。設定のパッド操作とLAN接続先の入力を追加。現行の操作は[LAN_CONNECTION_GUIDE.md](LAN_CONNECTION_GUIDE.md)を参照。対応範囲は同じLAN内。
