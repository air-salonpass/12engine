# 日本語の項目名とマウスによる説明

Hierarchy / Inspector / Project / Scene / Gameなどの枠名はそのままにし、設定名・操作名・選択肢を日本語で表示します。モデルやファイルの名前、ゲームが判定するタグ文字列、保存データのキーはそのままです。

## 操作する人へ

項目名、入力欄、チェックボックス、ボタンへマウスを合わせると説明が出ます。クリックする必要はありません。プレイ中に編集できない設定も説明を読めます。配置・当たり判定・移動・Player・カメラ・光・反射・画面効果・動作速度の各項目に、用途・単位・変更の目安・現在の制限を記載しています。

例えば「登れる段差の高さ (m)」では0で無効、見本の設定は0.45m、頭上が塞がる場所には登らないことを確認できます。「傾斜の上限」は保存される値ですが現在の判定には使わないため、表示名にも未対応と記載しています。「ダッシュの倍率」は歩く速さへ掛ける値です。

日本語の項目名がInspectorの横幅から切れないよう、数値や選択肢の名前は入力欄の上に表示します。数値欄のドラッグ、直接入力、Ctrl+Zの取消しは従来どおりです。

Projectでは「サンプル」から機能見本へ移動できます。ファイルへマウスを合わせると、開いた場合にシーンを置き換えるか、部品を追加するかを説明します。Hierarchyの物体名は利用者が付けた名前を維持します。

## 実装する人へ

1. `DirectX12/EditorUiHelp.h` の `entries` に、固定キー・日本語の表示名・日本語の説明を追加します。説明は代入の言い換えではなく「何に使うか」「単位」「使う際の条件」「未対応の部分」を書きます。現在の動作とコードを照合してください。
2. `NativePreview.cpp` のUIには `editor_ui::SliderFloat`、`Checkbox`、`Combo`、`Button` などを使います。引数は従来のImGui呼出しと同じです。値や保存処理を翻訳表へ入れないでください。
3. 入力欄は日本語名と内部キーを分けて描き、ボタンは `表示名###固定キー` にします。固定キーは今後の表示名修正でも変えません。これはJSONのキーやComponent登録とは別のUI上の識別です。
4. `explain` は直前の項目へマウスが重なっている場合だけ、折り返し付きの説明を出します。無効な項目も対象です。説明内へ入力欄やボタンを追加しないでください。呼出し元の `IsItemActivated` とUndo記録が元の編集項目を判定できるようにします。
5. 新Componentの値を編集する場合は引き続き `record_component_edit()` を呼び、Scene/Prefabの保存・読込みも追加します。今回の日本語化は表示だけなので保存形式、複製、Undoのデータ構造は変更していません。
6. Debugでマウスによる説明、数値変更、取消し、Comboの選択、プレイ中に無効な設定の説明を確認します。ReleaseはEditor UIを含まないため、このヘッダーも `USE_IMGUI` の場合だけ定義されます。両構成をビルドしてUI以外へ依存を持ち込まないことを確認します。

第三者ライブラリのUIやコメントは一括翻訳しません。参考フォルダーは編集せず、エンジン独自の画面と説明をこのヘッダーで管理します。
